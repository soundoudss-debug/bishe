# 项目结构说明（通俗版）

## 一、一句话理解这个项目

把整个系统想象成一个**广播电台**：

- **识别模块**是"播音员"，它只负责看摄像头、判断你做的是哪个手势，然后把结果"广播"出去；
- **音频、视觉、学习、录制、界面**是"听众"，各自守在收音机前，听到广播后只做自己那一件事；
- 它们之间**互不认识、不直接打电话**，全部通过中间的"电台"（事件总线）传话。

这样做的好处是：任何一块出问题或要改动，都不会牵连其他部分；想加新功能，只要再添一个"听众"就行。

## 二、数据是怎么流动的

```
摄像头画面
   │  （手部关键点 landmarks）
   ▼
识别状态机（09）：分类 → 防抖确认 → 握拳门控
   │  只发事件，不碰别的模块
   ▼
事件总线 AppBus（00）
   ├─► 音频模块（08）：发声 / 停音
   ├─► 视觉模块（07）：粒子球变色、张开，音符大字
   ├─► 学习模块（11）：判断对错、计分
   ├─► 录制模块（12）：把音符写进时间轴
   └─► 界面模块（16）：摄像框文字、警告提示
```

关键点：**音频和视觉模块再也看不到手部关键点**，它们只收到"音符名、置信度、时间戳"这样的标准消息。

## 三、事件协议（"电台"广播的内容）

| 事件名 | 什么时候发 | 携带的信息 |
|---|---|---|
| `gesture:note` | 确认一个有效音符 | `note` 音符名（do…si）、`confidence` 置信度(0~1)、`timestamp` 时间戳 |
| `gesture:release` | 握拳复位 / 切换模式，停止当前音 | `timestamp` 时间戳 |
| `gesture:fist` | 确认拳头（复位态） | `confidence`、`timestamp` |
| `gesture:invalid` | 手势无效 | `timestamp` |
| `gesture:status` | 每一帧都发，给界面用 | `hasHand` 是否看到手、`stable` 当前稳定手势、`armed` 是否可奏下一音 |

## 四、每个文件是干什么的

### 入口与样式
- **index.html**：整个页面的骨架。负责摆放摄像头框、按钮、手势图、各模式面板，并按顺序加载所有脚本。
- **styles/main.css**：所有外观样式（颜色、布局、动画、按钮），管"长什么样"。

### 脚本（按加载顺序）
- **00-event-bus.js**：事件总线，就是上面说的"电台"。提供 `on`（订阅）、`off`（取消）、`emit`（广播）三个能力。
- **01-config.js**：参数配置表。粒子数量、球体大小、浮动幅度、旋转速度等数字都集中在这里，调参数不用到处找。
- **02-scene.js**：搭建 Three.js 基础舞台——场景、相机、渲染器。
- **03-particles.js**：生成由 3000 个粒子组成的球形粒子系统。
- **04-visual-state.js**：视觉模块的"状态变量仓库"，记录当前音符、脉冲、当前模式，以及各音符对应的粒子颜色。
- **05-animate.js**：动画循环引擎。每帧根据当前音符/脉冲，让粒子球张开、变色、浮动并渲染。
- **06-gesture.js**：纯手势判定函数。输入手部关键点，输出是哪个音（Do/Re/…），不含任何界面和发声逻辑。
- **07-note-styles.js**：定义七个音符的文字、音高、颜色；包含 `setVisualNote`（切换视觉状态），并订阅手势事件来更新视觉。
- **08-audio.js**：音频模块。只负责合成器的起音和释音，通过订阅手势事件工作，不碰视觉和录制。
- **09-gesture-state.js**：识别状态机（核心）。负责防抖确认、握拳复位门控，然后把结果通过事件发出去；不直接调用任何其他模块、不操作界面。
- **10-carousel.js**：左下角七张手势指导图的自动轮播，图片和文字说明同步切换。
- **11-learn.js**：学习模式。包含八音跟练序列、对错判断、正确率统计；通过订阅事件接收手势。
- **12-create.js**：创作模式。负责录音、暂停、停止、回放，以及把音符事件写进录制时间轴；通过订阅事件记录演奏。
- **13-mode-switch.js**：模式切换（探索/学习/创作）。切换时通过发"释音事件"干净地收掉当前音，而不是直接调音频函数。
- **14-boot.js**：启动流程。点击"启动摄像头"后，依次开启摄像头、合成器、内录器、MediaPipe 识别。
- **15-resize.js**：窗口大小变化时，自动调整相机和渲染尺寸。
- **16-status-ui.js**：摄像框界面控制器。只订阅状态事件，刷新摄像框文字和"未识别"警告，本身不做判定。

## 五、重构前后的区别

- **重构前**：识别模块直接命令音频发声、命令视觉变色、还自己改界面文字；一个 `setActiveNote` 函数里同时混着发声、录制、改视觉三件事，模块之间靠全局变量互相改写，牵一发而动全身。
- **重构后**：识别模块只发标准事件，音频、视觉、学习、录制、界面各自订阅、各管一摊。**功能和实际表现完全没变**，但边界清晰、更容易调试和继续加功能。
